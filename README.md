# ECDR — Evidence-Guided Open-Ended Engineering Design

> 本仓库源于 2026-10-12 的一次研究讨论（原文见 [`docs/reference/seed-conversation.md`](docs/reference/seed-conversation.md)）。
> **当前状态：立项与定题阶段（charter draft）。技术路线尚未冻结，见文末"待决问题"。**

## 1. 一句话愿景

让 AI Agent 在**多保真物理验证反馈**下，识别工程失败的**原因**，自主**改写问题的分解方式与设计机制**，管理多条**非单调**探索路径，并最终交付经过**独立物理验证**的工程方案。

## 2. 核心科学问题

> **Can an AI agent recognize when its current engineering design paradigm is fundamentally inadequate, and autonomously discover a better one through physical evidence?**
>
> AI Agent 能否根据物理证据，识别当前设计范式的根本局限，并自主探索出更合适的工程方案？

关键不在 *Design*，而在 **Paradigm Change**：从"解空间**搜索**"升级到"解空间**重构**"。

## 3. 问题形式化

传统优化假设解空间已知：

$$\min_{\theta \in \Theta} f(\theta)$$

真实工程设计需要改变解空间本身。把设计对象写成三元组：

$$D = (G,\ m,\ \theta)$$

- $G$：**问题分解结构**（把问题切成哪些子问题）
- $m$：**设计机制**（用什么物理机制解决），每个机制有自己的参数空间 $\Theta_m$
- $\theta$：该机制下的**具体设计参数**

对应四个层次的干预深度：

| 层次 | Agent 能做什么 | 振动抑制示例 |
|---|---|---|
| Parameter Refinement | 调整既有参数 | 增大阻尼系数 |
| Structural Redesign | 改变设计结构 | 增加辅助质量块 |
| Mechanism Switching | 更换物理解决机制 | 被动减振 → 主动控制 |
| Problem Reframing | 改变问题分解方式 | 从"单纯抑制振动" → "联合优化结构 + 传感 + 控制" |

**真正的研究问题不是"让 Agent 四层都会"，而是：Agent 凭什么证据决定，什么时候应该停止参数优化、转而改变更高层次的设计？**

## 4. 方法与命名（⚠️ 命名尚未统一，需拍板）

种子对话里出现了**三个不同的名字**，必须在写作前统一：

| 名字 | 出现位置 | 含义 |
|---|---|---|
| **Evidence-Guided Open-Ended Engineering Design** | 用户开场 + 第一节 | 整个**研究方向** |
| **ECDR** = *Evidence-Conditioned* Design-Space Revision | 第三节标题 | **方法**（"Conditioned"） |
| **ECDR** = *Evidence-Driven* Design-Space Revision | 第六节 | 同一方法的另一种展开（"Driven"） |

仓库目录名 `ECDR` 对两种展开都成立，但论文必须只留一个。建议：方向用 **Evidence-Guided Open-Ended Engineering Design**，方法用 **ECDR = Evidence-Conditioned Design-Space Revision**（"条件化"更准确地表达"证据决定**允许搜索的空间**"，而不只是"驱动一次修改"）。

### ECDR 的核心思想

**不把一次仿真失败直接转成修改建议**，而是：

1. 把失败转成**若干互相竞争的原因假设**；
2. 设计**能区分这些假设的针对性实验**（可证伪性）；
3. 实验不仅更新对物理机制的认知，**还要改变接下来允许探索的设计空间与问题分解结构**；
4. 据此选择 Refine / Revise / Branch。

候选架构（种子对话原文）：

```
Engineering Goal
      ↓
Design Hypothesis Graph        （机制、问题分解、候选分支及各自物理假设）
      ↓
Multi-Fidelity Physics Evaluation   （低成本模型 → 精细仿真与扰动实验）
      ↓
Causal Failure Diagnosis       （提出失败假设、选择区分实验、更新证据置信度）
      ↓
   ┌──────────┬──────────┬──────────┐
 Refine      Revise      Branch
 局部改进     机制转换     保留/恢复路线
   └──────────┴──────────┴──────────┘
      ↓  （更新设计图，重新探索）
Independent Physical Validation   （隐藏工况、独立验证器，条件允许时实体实验）
```

## 5. 两个必须解决的技术难点

### 5.1 失败诊断必须有物理可证伪性
例：散热装置温度过高，三种竞争解释要有各自的**可检验预测**（散热面积不足 / 流动阻力过大 / 当前散热机制能力受限）。Agent 必须选择**能区分它们的实验**。
→ 但注意：**"假设竞争 + 主动实验"已有先行工作**（见 landscape），因此这本身不是贡献；贡献必须落在"实验结果改写设计空间"。

### 5.2 不能把连续失败等同于机制不可能成功
必须严格区分：

> **"还没有找到可行解"** vs **"有证据表明当前设计空间不存在可行解"**

禁止用 "连续失败 N 次 → 放弃机制" 这种规则。应使用物理必要条件、可计算性能界限、局部灵敏度、针对性扰动与不确定性估计。
→ **这可能是本项目最有机会做出硬贡献的地方**：把"逃逸"的触发条件建立在**可证明的不可行性**上，而不是启发式计数。

## 6. 第一个实验场景：精密定位系统振动抑制

| 保真度 | 验证方式 | 在研究中的作用 |
|---|---|---|
| **L0** | 解析模型、线性系统频率响应 | 快速排除明显不合理方案 |
| **L1** | 含非线性、饱和、扰动的数值仿真 | 评估更真实的动态行为 |
| **L2** | 独立仿真实现或实验台架 | 在**未参与搜索**的条件下评估最终方案 |

⚠️ 必须区分 *independent numerical validation* 与 *experimental physical validation*，不能混为一谈。

**初始机制**：单自由度被动隔振 $m\ddot{x} + c\dot{x} + kx = F(t)$，只调 $k, c$。
**期望行为**：不是"第 17 次尝试：继续增大阻尼"，而是"当前被动单自由度系统存在无法通过现有参数调整消除的性能权衡，需检验引入附加动力学自由度或主动控制"。
**逃逸方向**：调谐质量阻尼器（TMD）、重新构造机械传递路径、主动反馈控制。
**第一篇论文只需要证明**：Agent 能在**有证据支持**的条件下主动改变设计机制，而不是困在初始参数空间。

## 7. 评价体系

专门构造 **Design-Space Escape Tasks**：初始机制经参数优化仍不满足约束，但存在**另一类机制**可达成目标。
**关键**：对低维/受限设计空间，要用解析界限、可靠全局求解或可复核穷举来**确认初始机制不可行**，而不是"我们没找到解就说它不可行"。

| 实验问题 | 核心指标 |
|---|---|
| Agent 能否识别失败的真正原因？ | 干预验证的诊断准确率 |
| Agent 能否逃离受限设计空间？ | Escape Success Rate |
| Agent 能否高效使用实验资源？ | 达到有效解的累计仿真成本 |
| 是否真的需要多条非单调路径？ | 移除分支恢复能力后的性能变化 |
| 最终方案是否真正可靠？ | 独立验证成功率 + 工况外鲁棒性 |

**基线**：普通 LLM / ReAct / Plan–Execute–Reflect Agent；预算一致的多分支搜索；贝叶斯优化；进化算法；成熟工程优化器（含拓扑优化）。
**公平性硬要求**：强基线必须能访问**同一套设计生成算子与机制集合**。

## 8. 范围纪律（防止论文做太大）

同时宣称"物理失败诊断 + 问题分解重构 + 机制转换 + 非单调树搜索 + 多保真调度 + 独立验证"六个创新 = 每个都不深。**只留一个主创新**：

> **ECDR：利用经过物理实验检验的失败证据，决定何时以及如何修改工程设计空间。**

其余各就各位：多分支记忆 = 实现它的搜索机制；多保真验证 = 获取证据的工具；独立验证 = 评价标准。

**可证伪的论文假设**：

> 相比仅依据性能分数不断修改候选方案的 Agent，能够区分**参数失败**与**机制失败**并据此重构设计空间的 Agent，在固定验证预算下能更有效地找到**独立验证通过**的工程设计。

**关于 "Open-Ended" 的克制**：如果 Agent 只能从预先列好的三种机制里选，本质仍是**离散机制搜索**。只有当它能组合/增加/修改设计算子、使可搜索空间发生**可验证的扩展**时，*open-ended* 才有依据。

候选标题：**Beyond Local Refinement: Evidence-Guided Design-Space Revision for Physically Verified Engineering Agents**

## 10. 待决问题（阻塞后续设计）

### 🔴 Q1（种子对话最后留下的根本分歧）
**我们究竟希望 Agent 学会"什么时候放弃一条设计路线"，还是"如何创造一条以前不存在的设计路线"？**

- 前者 = 有物理证据支持的**自适应搜索与决策** → 算法与评估体系可做严谨。
- 后者 = 更接近真正的**工程创造力** → "创新"的定义、可执行表示、客观评估都难得多。

种子对话的倾向：**把前者做成扎实的技术核心，同时通过可组合、可扩展的设计空间去触及后者。** 需确认。

### 🔴 Q2（尚未讨论过）
**"可证明的不可行性"用什么数学工具落地？** 这是 5.2 能否成为硬贡献的关键。振动抑制场景下可用的候选：结构奇异值 / $H_\infty$ 范数下界、Bode 灵敏度积分（水床效应）、无源性与执行器权限约束、质量/能耗约束下的可达性能界限。需要选定并在 L0 层实现为**可调用的不可行性证书（infeasibility certificate）**。

### 🟡 Q3
**诊断的 ground truth 从哪来？** 要报告"诊断准确率"，就必须有已知的失败原因标签。可行做法：在 benchmark 里**构造**失败（参数受限 vs 机制受限），把标签作为隐藏真值。
