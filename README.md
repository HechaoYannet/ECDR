# ECDR — Evidence-Guided Open-Ended Engineering Design

> 本仓库源于 2026-10-12 的一次研究讨论（原文见 [`docs/reference/seed-conversation.md`](docs/reference/seed-conversation.md)）。
> **当前状态：立项与定题阶段（charter draft）。技术路线尚未冻结，见文末"待决问题"。**

## 1. 一句话愿景

让 AI Agent 在**多保真物理验证反馈**下，识别工程失败的**原因**，自主**改写问题的分解方式与设计机制**，管理多条**非单调**探索路径，并最终交付经过**独立物理验证**的工程方案。

## 2. 核心科学问题

> **Can an AI agent recognize when its current engineering design paradigm is fundamentally inadequate, and autonomously discover a better one through physical evidence?**
>
> AI Agent 能否根据物理证据，识别当前设计范式的根本局限，并自主探索出更合适的工程方案？

关键不在 *Design*，而在 **Paradigm Change**：从"解空间**搜索**"升级到"解空间**重构**"。

## 3. 问题形式化

传统优化假设解空间已知：

$$\min_{\theta \in \Theta} f(\theta)$$

真实工程设计需要改变解空间本身。把设计对象写成三元组：

$$D = (G,\ m,\ \theta)$$

- $G$：**问题分解结构**（把问题切成哪些子问题）
- $m$：**设计机制**（用什么物理机制解决），每个机制有自己的参数空间 $\Theta_m$
- $\theta$：该机制下的**具体设计参数**

对应四个层次的干预深度：

| 层次 | Agent 能做什么 | 振动抑制示例 |
|---|---|---|
| Parameter Refinement | 调整既有参数 | 增大阻尼系数 |
| Structural Redesign | 改变设计结构 | 增加辅助质量块 |
| Mechanism Switching | 更换物理解决机制 | 被动减振 → 主动控制 |
| Problem Reframing | 改变问题分解方式 | 从"单纯抑制振动" → "联合优化结构 + 传感 + 控制" |

**真正的研究问题不是"让 Agent 四层都会"，而是：Agent 凭什么证据决定，什么时候应该停止参数优化、转而改变更高层次的设计？**

## 4. 方法与命名（⚠️ 命名尚未统一，需拍板）

种子对话里出现了**三个不同的名字**，必须在写作前统一：

| 名字 | 出现位置 | 含义 |
|---|---|---|
| **Evidence-Guided Open-Ended Engineering Design** | 用户开场 + 第一节 | 整个**研究方向** |
| **ECDR** = *Evidence-Conditioned* Design-Space Revision | 第三节标题 | **方法**（"Conditioned"） |
| **ECDR** = *Evidence-Driven* Design-Space Revision | 第六节 | 同一方法的另一种展开（"Driven"） |

仓库目录名 `ECDR` 对两种展开都成立，但论文必须只留一个。建议：方向用 **Evidence-Guided Open-Ended Engineering Design**，方法用 **ECDR = Evidence-Conditioned Design-Space Revision**（"条件化"更准确地表达"证据决定**允许搜索的空间**"，而不只是"驱动一次修改"）。

### ECDR 的核心思想

**不把一次仿真失败直接转成修改建议**，而是：

1. 把失败转成**若干互相竞争的原因假设**；
2. 设计**能区分这些假设的针对性实验**（可证伪性）；
3. 实验不仅更新对物理机制的认知，**还要改变接下来允许探索的设计空间与问题分解结构**；
4. 据此选择 Refine / Revise / Branch。

候选架构（种子对话原文）：

```
Engineering Goal
      ↓
Design Hypothesis Graph        （机制、问题分解、候选分支及各自物理假设）
      ↓
Multi-Fidelity Physics Evaluation   （低成本模型 → 精细仿真与扰动实验）
      ↓
Causal Failure Diagnosis       （提出失败假设、选择区分实验、更新证据置信度）
      ↓
   ┌──────────┬──────────┬──────────┐
 Refine      Revise      Branch
 局部改进     机制转换     保留/恢复路线
   └──────────┴──────────┴──────────┘
      ↓  （更新设计图，重新探索）
Independent Physical Validation   （隐藏工况、独立验证器，条件允许时实体实验）
```

## 5. 两个必须解决的技术难点

### 5.1 失败诊断必须有物理可证伪性
例：散热装置温度过高，三种竞争解释要有各自的**可检验预测**（散热面积不足 / 流动阻力过大 / 当前散热机制能力受限）。Agent 必须选择**能区分它们的实验**。
→ 但注意：**"假设竞争 + 主动实验"已有先行工作**（见 landscape），因此这本身不是贡献；贡献必须落在"实验结果改写设计空间"。

### 5.2 不能把连续失败等同于机制不可能成功
必须严格区分：

> **"还没有找到可行解"** vs **"有证据表明当前设计空间不存在可行解"**

禁止用 "连续失败 N 次 → 放弃机制" 这种规则。应使用物理必要条件、可计算性能界限、局部灵敏度、针对性扰动与不确定性估计。
→ **这可能是本项目最有机会做出硬贡献的地方**：把"逃逸"的触发条件建立在**可证明的不可行性**上，而不是启发式计数。

## 6. 第一个实验场景：精密定位系统振动抑制

| 保真度 | 验证方式 | 在研究中的作用 |
|---|---|---|
| **L0** | 解析模型、线性系统频率响应 | 快速排除明显不合理方案 |
| **L1** | 含非线性、饱和、扰动的数值仿真 | 评估更真实的动态行为 |
| **L2** | 独立仿真实现或实验台架 | 在**未参与搜索**的条件下评估最终方案 |

⚠️ 必须区分 *independent numerical validation* 与 *experimental physical validation*，不能混为一谈。

**初始机制**：单自由度被动隔振 $m\ddot{x} + c\dot{x} + kx = F(t)$，只调 $k, c$。
**期望行为**：不是"第 17 次尝试：继续增大阻尼"，而是"当前被动单自由度系统存在无法通过现有参数调整消除的性能权衡，需检验引入附加动力学自由度或主动控制"。
**逃逸方向**：调谐质量阻尼器（TMD）、重新构造机械传递路径、主动反馈控制。
**第一篇论文只需要证明**：Agent 能在**有证据支持**的条件下主动改变设计机制，而不是困在初始参数空间。

## 7. 评价体系

专门构造 **Design-Space Escape Tasks**：初始机制经参数优化仍不满足约束，但存在**另一类机制**可达成目标。
**关键**：对低维/受限设计空间，要用解析界限、可靠全局求解或可复核穷举来**确认初始机制不可行**，而不是"我们没找到解就说它不可行"。

| 实验问题 | 核心指标 |
|---|---|
| Agent 能否识别失败的真正原因？ | 干预验证的诊断准确率 |
| Agent 能否逃离受限设计空间？ | Escape Success Rate |
| Agent 能否高效使用实验资源？ | 达到有效解的累计仿真成本 |
| 是否真的需要多条非单调路径？ | 移除分支恢复能力后的性能变化 |
| 最终方案是否真正可靠？ | 独立验证成功率 + 工况外鲁棒性 |

**基线**：普通 LLM / ReAct / Plan–Execute–Reflect Agent；预算一致的多分支搜索；贝叶斯优化；进化算法；成熟工程优化器（含拓扑优化）。
**公平性硬要求**：强基线必须能访问**同一套设计生成算子与机制集合**。

## 8. 范围纪律（防止论文做太大）

同时宣称"物理失败诊断 + 问题分解重构 + 机制转换 + 非单调树搜索 + 多保真调度 + 独立验证"六个创新 = 每个都不深。**只留一个主创新**：

> **ECDR：利用经过物理实验检验的失败证据，决定何时以及如何修改工程设计空间。**

其余各就各位：多分支记忆 = 实现它的搜索机制；多保真验证 = 获取证据的工具；独立验证 = 评价标准。

**可证伪的论文假设（2026-10-12 依据文献证据修订）**：

> 在**固定机制清单**与**固定评估预算**下，依据**可证明的不可行性**剪枝的工程设计 Agent，比依据性能分数、连续失败次数或代理模型预测剪枝的 Agent，能更频繁、更低成本地逃出已被证明不可行的设计空间——且优势随可行机制变得**稀疏**而增大。

三个使它可证伪且公平的约束：
- **机制清单在两组之间固定**，否则实验测的是"选项更多"而非"证据用得更好"；
- 证书由**独立代码路径**生成与校验，Agent 不能自己出具证明；
- 主指标是 **Escape Rate**，同时报告成本账本，使"逃逸"不能等价于"花得更多"。

**关于 "Open-Ended" 的克制（现在有实证支撑）**：
Heuresis（arXiv 2606.25198）3,222 次评分运行、六种主流开放式/质量-多样性策略，**没有一个想法被评为 "Original"**，最好只到 "Minor Similarity"，严格 top-10 ∩ 新颖侧**只有 1 个想法**；质量-新颖 Pareto 前沿是"被重新占据"而非"被推动"。AlphaEvolve 展示了**代码级组件的引入**（新增三个 ResNet block、Adam→AdamW），但**机制类别层面的引入在任何一篇中都没有出现**。
因此 *open-ended* 只能这样挣得：Agent 可以提出机制清单的扩展，但扩展只有在**附带证书或见证**之后才被纳入**可采纳集合**。这是"可采纳集合的证书化扩张"，不是"LLM 有创造力"。

候选标题：**Beyond Local Refinement: Certified Infeasibility as a First-Class Design Action**

### 多保真阶梯（[findings/008](docs/findings/008-l1-rung-and-false-positive-zone.md)）

**设计规则**：L1 只**增加**约束、绝不放松。因此「L1 可行 ⟹ L0 可行」，逆否即 **「L0 不可行 ⟹ L1 不可行」**——**不可行性证明在所有更高保真度上都成立，而 L0 的见证在 L1 上什么也不说明**。证书能剪枝、不能构造，这正是 Finding 005 从文献推出的结论，现在是代码的性质而非主张。

| 要求 | 无源单自由度可行阈值 | 相对 L0 偏移 |
|---|---|---|
| L0（无扰动） | **172.34 Hz**（精确） | — |
| L1，±5% | 203.10 Hz | +30.76 Hz |
| L1，±10% | **239.72 Hz** | **+67.38 Hz** |

**假阳性区**：在 **172.34 < f_low < 239.72 Hz** 之间，L0 证书宣布 M1 **可行**，而没有任何设计能在 ±10% 扰动下存活（180/200/220/240 Hz 处违反量单调递减 +0.1411 → +0.0101，260 Hz 起转负）。**这就是 L0 实验所缺的那个区制**：证书对剪枝仍然可靠，但对可行性的判断不再成立，于是 agent 必须真的搜索。

### 逃生阶梯（[findings/006](docs/findings/006-labelled-task-family.md)）

| 频带边缘 | M1 无源单自由度 | M2 调谐质量阻尼器 | M3 sky-hook 主动 | 最小可解机制 |
|---|---|---|---|---|
| < 132.43 Hz | **可证不可行** | 无见证 | 可行 | M3 |
| 132.43–172.24 Hz | **可证不可行** | 可行 | 可行 | M2 |
| > 172.24 Hz | 可行 | 可行 | 可行 | M1 |

两个阈值：M1→M2 = **172.237063 Hz（精确）**，M2→M3 = **132.4253 Hz（数值）**。

## 10. Q1 / Q2：已由文献证据裁定（详见 [docs/findings/003](docs/findings/003-q1-q2-evidence-synthesis.md)）

### ✅ Q2 = 主线（承担主要贡献）

**Q2 不是被我们提出的，而是被最接近的可比工作指认为"缺失的那个能力"。**
Heuresis 第 6.1 节原文：

> "Search needs a signal that decides, for a novel-but-currently-weak idea, whether it is weak because the mechanism itself is bad or because the first-attempt execution simply has not been optimized."

这正是种子对话 5.2 的独立重述。Heuresis 说没有任何一种被测策略能做这个区分，而这正是新想法被丢弃的原因。
**我们的不对称优势**：Heuresis 把它当成**保留/假阴性**问题，想要一个*预测器*；ECDR 把它当成**剪枝/假阳性**问题，给出的是*可证明的闭式证书*。预测器会错，证明不会。

**而且"用数学"这个直觉需要一处关键修正。** Agent 已被验证的优势区间**不是 "verifier-guided search"** —— arXiv 2502.00271 恰恰证明它会崩：样本量 1 时领先，样本量 32 时在 MATH 上落后约 20%，OOD-L5 上落后 32.8%；失败中 **77–88% 是 SELECTION 失败**（有效路径被生成后又被丢掉）；最好的补救办法居然是**完全不用 verifier 的分数**。
真正的优势区间是 **sound verification + 在"已证伪"之上的策略搜索**。这就是为什么资产是**证书**，不是搜索策略。我们的 $\Lambda$ 证书属于 CORE（arXiv 2609.39069）三级分类中的**第一级（exact）**，位于 2502.00271 失效层级之上。

**剪枝规则必须满足的 9 条性质（P1–P9）** 见 findings/003 第 1.4 节。核心是 CORE 的 **exhaustion core**：放弃一个**机制类**，等价于对该类**每一个**合法备选都持有已认证的 core，然后取并集消去该决策层——这要求对**整个可行参数集**证明，而不是对采样点。CORE 明说了这个陷阱：
> "Running out of sampled candidates in one proposal batch does not establish exhaustion."

### ✅ Q1 = 降级为支撑（路由 + 清单维护）

Q1 不能作为贡献，原因**是实证的**：Heuresis 3,222 次运行零个 Original。但 Q1 并未消失，它变成：

> **给定每个任务的机制清单，把设计路由到可行集包含解的那个机制类，并把清单作为显式、可版本化、可认证的产物来维护。**

这是**决策问题，不是生成问题**，而且 M1/M2/M3 阶梯已经就是它。机制类的差别是真实且可度量的：M1 与 M3 的传递函数**只差分子上的一项**（阻尼馈通项），而正是这一项使任务对 M1 可证不可行、对 M3 可解。

### ✅ Q3（诊断 ground truth）已顺带解决
扫掠频带边缘即可生成**带真值标签的 escape 任务族**：$\Lambda < 1$ 给出 M1 可证不可行，而被动两自由度（TMD）的阈值落在 110–160 Hz 之间。每个任务天然的标签就是"能解它的最小机制类"。
